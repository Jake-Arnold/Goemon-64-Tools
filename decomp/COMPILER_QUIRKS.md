### `GLOBAL_ASM` final-function padding changes `STT_FUNC` size; preserve linker-owned alignment — verified original-upstream

- **Region / original functions / offsets / VMAs:** USA main, `func_8000AB30_B730` ROM `0xB730`, guest `0x8000AB30` (new 68-byte C); unchanged neighbouring `func_8000AFA8_BBA8` ROM `0xBBA8`, guest `0x8000AFA8` (752-byte ASM). Other C in the tested unit: `func_8000AAE8_B6E8` ROM `0xB6E8`, guest `0x8000AAE8` (40 bytes), and `func_8000A18C_AD8C` ROM `0xAD8C` (48 bytes).
- **Compiler, assembly processor, flags:** original SGI IDO 5.3 (`cc` SHA-256 `76d796c9591c9f5504949f85b29c32a6039a663791afe2f36f34ca18425b64d0`), vendored Rust `asm-processor` SHA-256 `d3c002fbb630b18117f4ca4e799516fb78012120469518352dae678e8c68abb9`. IDO: `-c -G 0 -non_shared -Xfullwarn -Xcpluscomm -Wab,-r4300_mul -woff 649,838,712 -D_LANGUAGE_C -D_FINALROM -DF3DEX_GBI -D__sgi -DNDEBUG -O2 -mips2`; assembler: `-EB -mtune=vr4300 -march=vr4300 -mabi=32`. Original pinned upstream `mnsg@7e2029c5c7beca705e7ded2c8fa85a5a21d1c3ee`, Splat 0.36.3.
- **Minimal source / reproduction:** `decomp/research/usa_unique_three_20261122/verify_original_unit.py`, paired with `source/func_8000AB30_B730.c` and `source/func_8000AAE8_B6E8.c` in that research directory. Original `config/usa/splat.yaml`: `[0xB280, asm]`, `[0xBEA0, asm]`. Reconstructed: `[0xB280, c, research_mixed_b280]`, **retain `[0xBEA0, asm]`**; do not extend the embedded C/ASM segment through the following original functions. Original generated `asm/usa/nonmatchings/research_mixed_b280/func_8000AFA8_BBA8.s` has two zero NOP instructions **after its `endlabel`**, at ROM `0xBE98` and `0xBE9C`. The source-only verifier checks exactly those positions, then strips *only the two unowned padding instructions* from this generated embedded-ASM fragment **after Splat regeneration but before the native build**; original linker 16-byte segment alignment reintroduces the same eight zero bytes at the same ROM positions. It neither rewrites the function body nor adds a synthetic function symbol.
- **Observed versus expected:** With those NOPs left inside one embedded `GLOBAL_ASM` pragma, assembler processor assigns the unchanged neighbouring ELF `FUNC` symbol **760 bytes**, although original ELF gives **752**, even with a standalone `.size ... 0x2F0` declaration; the associated `.NON_MATCHING` `OBJECT` size remains 752. Under standalone GNU `as` (same actual original ASM fragment and macros), the `FUNC` size is correctly 752, isolating the discrepancy to the mixed-object injection. The ROM nevertheless matches all 33,554,432 bytes and all 82,216 original-upstream relocation records—**ROM equality alone does not prove ELF metadata equality**. The fix yields neighbouring `FUNC` **752**, the new 68-byte target **68**, complete original 33,554,432-byte ROM equality, all **7,376/7,376 positive-sized ELF function identities** and all **82,216/82,216 relocation records** equal by section/offset/type/symbol.
- **Failed alternatives (directly measured):** An anonymous embedded `.text` NOP block is rejected by asm-processor (`.text block without an initial glabel`); `.set noreorder` rejected (`asm directive not supported`); `.align 4` rejected (`only .align 2 is supported`); grouping the neighbouring 752-byte function together with the next original function inside one pragma gave an incorrect 956-byte first `FUNC`; merely moving the trailing NOPs out of the pragma but leaving the next function in the same mixed C unit moved the following symbol eight bytes early. Writing `.size func_8000AFA8_BBA8, 0x2F0` after the two NOPs worked in standalone GNU `as` but **did not** correct the asm-processor-injected `FUNC` size. Moving the source-unit split to `0xC1D0` while retaining the NOPs also failed. These are not portable workarounds.
- **Verification and evidence:** On 22 November 2026, run `python3 decomp/research/usa_unique_three_20261122/verify_original_unit.py --checkout /PRIVATE/pinned/mnsg --deps /PRIVATE/goemon-dependencies --runtime /PRIVATE/goemon-runtime-additions --out /PRIVATE/NEW-output --jobs 16`; see `decomp/research/usa_unique_three_20261122/evidence_padding_fixed.json`. Source-only mock-input invariant tests: `python3 -m unittest discover -s decomp/research/usa_unique_three_20261122/tests -p test_padding.py -v`. Host GCC 14.2 and Clang 17 ASan/UBSan source regression: `bash decomp/research/usa_unique_three_20261122/tests/run_host.sh /PRIVATE/NEW-host-output` (4,096 cases per source). Pinned original-upstream full-ROM/ELF/relocation gates **PASS**; main decomp branch's **1,965 previously accepted USA C** combined `decomp.verify`, canonical **82,103** semantic relocation audit, strict inventory and full `decomp.local_ci` **NOT RUN**. No canonical C promotion.
- **Applicability and limitations:** Verified for this original-USA main-segment translation-unit layout and specific vendored asm-processor. The general lesson is to distinguish **original instruction-body function extent** from **unowned final padding**, especially when compiling mixed IDO C and embedded original ASM. Do not automatically strip trailing NOPs: delay-slot NOPs and legitimate function-body NOPs must never be removed. The exact two-NOP check and ELF/ROM gates are required here. Applicability to other files, JP region or other compiler versions is **unverified**.

## IDO 5.3 source-line boundary changes MIPS instruction scheduling — verified original-upstream, not canonical decomp G2

- **USA target:** `func_800108BC_114BC`, original ROM `0x114BC` (decimal 70,844), VMA `0x800108BC`, original size 40 bytes. Original global `D_800637C0_643C0` is a symbol-address operand in two display-list words; do not generalise its semantics beyond observed code.
- **Compiler and flags:** original SGI IDO 5.3, `-c -G 0 -non_shared -Xfullwarn -Xcpluscomm -Iinclude -Ilibultra/include -Ilibultra/include/PR -Isrc -I. -Wab,-r4300_mul -woff 649,838,712 -D_LANGUAGE_C -D_FINALROM -DF3DEX_GBI -D__sgi -DNDEBUG -O2 -mips2`.
- **Source/reproducer:** `decomp/research/usa_menu_40_combined4_20261122/source/func_800108BC_114BC.c`; `tests/test_ido_shapes.py` compiles it plus a same-token line-break-only negative control under native IDO and checks every untouched MIPS instruction and both symbol relocation offsets. Uses an 8-byte `struct { unsigned int w0,w1; }` and a deliberately single-line 10-instruction function body. `verify_original_combo.py` pins its source SHA-256 to prevent formatting drift.
- **Measured difference:** same-line assignments emit `lui t7, %hi(D)` then `addiu t7, %lo(D)` then `lui t6, 0x600`, with original `R_MIPS_HI16` at object offset `+0` and `R_MIPS_LO16` at `+4`. Inserting only a newline after `p->w0=0x06000000;` changes ordering to `lui t7`, `lui t6`, `addiu t7`; LO16 moves from `+4` to `+8` despite unchanged C semantics. Both variants are 40 bytes. This was reproduced with original `tools/ido-5.3/cc`; not based on a surrogate host compiler. Adding comments or blank lines *before* the function and changing `unsigned` to `unsigned int` does **not** change codegen.
- **Confounding control:** an SDK `Gfx` union with all function-body statements grouped on one source line emits the same exact instructions as the raw 2-word struct; the earlier hypothesis that `Gfx` union alone caused relocation drift was **falsified**. Flattened `u32*` pointer access can change *later* store scheduling. Do not attribute the issue to SDK type definitions.
- **Working constraint:** preserve the proven source-line grouping and source hash. Do not automatically format native-exact IDO C. All ten original instructions and symbolic relocations exact; complete authentic pinned original-upstream 32 MiB USA ROM, 7,376 ELF FUNC identities, 82,216 original-upstream relocations exact including other three research C functions. **Canonical 1,965-accepted-C decomp.verify and full CI NOT_RUN**.
- **Confidence:** direct compiler and whole-original-ROM evidence for this source and exact flags. Compiler scheduling sensitivity may be broader, but no universal line-break rule is asserted. Original shader/display-list behaviour beyond these two words is uninvestigated.

## Splat/asm-processor cannot preserve rodata jump-table labels across a whole-unit GLOBAL_ASM split — verified integration constraint

- **USA location:** source segment ROM `0x10D80..0x12760`, VMA main segment corresponding range; target `func_800108BC_114BC` at ROM `0x114BC`, VMA `0x800108BC`.
- **Toolchain:** original SGI IDO 5.3 and vendored `asm-processor`, Splat 0.36.3, MIPS GNU binutils 2.45.90, original `-O2 -mips2` flags.
- **Failure:** changing all of original `[0x10D80, asm]` to a mixed C translation unit with all 42 functions as C or `GLOBAL_ASM` loses externally referenced intra-function `.L...` jump-table target symbols from original rodata. The original native link then emits `undefined reference to .L800109C4_115C4` and `.L80011254_11E54` (among others); this is a **link failure**, not a native-code mismatch. Merely matching the target C in isolation does not fix this.
- **Successful workaround:** keep ASM for the original jump-table functions; create mixed C/ASM **only for original 16-byte-aligned window ROM `0x112F0..0x11580`** (six functions, five `GLOBAL_ASM` plus C target). Original preceding/following ASM units retain their original rodata-referenced labels. No jump-table address edits, synthetic labels or ROM patches. Full original-USA 32 MiB ROM and all ELF symbol/reloc identities exact.
- **Source/reproducer:** `decomp/research/usa_menu_40_combined4_20261122/verify_original_combo.py`, particularly the fail-closed YAML boundary injection and exact six-name source window; README contains the reproduction command and negative linker evidence.
- **Limits:** observed for this menu-graphics source unit and this Splat/asm-processor configuration. Not asserted to work for other segments without verifying their jump-table label references and 16-byte boundaries. Original-upstream exact only; **modern combined accepted-C G2 NOT_RUN**.

## IDO 5.3 source-line grouping determines register/prologue scheduling in original-USA structure copy and inclusive wrapper — VERIFIED native + complete pinned-original ROM

- **Region, original functions, ROM, guest VMA:** USA `func_8000A5C4_B1C4`, ROM `0xB1C4`, VMA `0x8000A5C4`, 80 bytes; `func_8000A548_B148`, ROM `0xB148`, VMA `0x8000A548`, 124 bytes. Both previously ASM-owned and distinct from verified accepted 1,956 and pending 51+48 donor research.
- **Toolchain:** genuine SGI IDO 5.3 from pinned `mnsg@7e2029c5c7beca705e7ded2c8fa85a5a21d1c3ee`, `-c -G 0 -non_shared -Xfullwarn -Xcpluscomm -Iinclude -Ilibultra/include -Ilibultra/include/PR -Isrc -I. -Wab,-r4300_mul -woff 649,838,712 -D_LANGUAGE_C -D_FINALROM -DF3DEX_GBI -D__sgi -DNDEBUG -O2 -mips2`. Original IDO compiler SHA-256 `76d796c9591c9f5504949f85b29c32a6039a663791afe2f36f34ca18425b64d0`.
- **Minimal source/reproducer:** `decomp/research/usa_92f0_six_originalrom_20261122/source/func_8000A5C4_B1C4.c` and `source/func_8000A548_B148.c`; `tests/test_ido_source_lines.py` recompiles both C bodies and negative controls under original IDO and compares original ROM function bytes at original VMA with proper relocation masking.
- **Copy behaviour and first mismatch:** a 38-u32 (0x98-byte) structure assignment from global `D_8005B974_5C574`, with destination word zero saved before assignment and restored afterward, emits exactly the original 20-instruction copy loop. A one-physical-line C formulation moves the `addiu $t9,$t6,0x90` loop bound calculation ahead of the `lw $v0,0($a0)` save; the original has `lw` first. With three statements on separate lines, ordering, loop branch/delay slot, full 80-byte FUNC extent and both R_MIPS_HI16/LO16 original-global relocations at `+0,+4` are exact. `void*` public parameter with a typed local pointer preserves original codegen while avoiding incompatible prototype from the preceding wrapper.
- **Wrapper behaviour and first mismatch:** `start*0x98` into the original `D_8008CCC0_8D8C0 + 0xBBB90` table followed by an inclusive loop using source expression `i < end+1` generates the original 31 MIPS instructions, `0x28`-byte stack frame and 124-byte `STT_FUNC`. On one physical source line, the compiler emits the `subu` before stack allocation at ROM `0xB154` (original allocates the frame first), and changes save-register/branch scheduling. On separate source lines the result is exact. Replacing `i < end+1` with `i <= end` is *not* the same native codegen: the `slt` direction and branch shape differ. Correct wrapper relocations: HI16 at `+0x28`, LO16 at `+0x38` against `D_8008CCC0_8D8C0`; 26-bit call at `+0x50` against `func_8000A5C4_B1C4`.
- **Trailing `.text` vs FUNC extent:** the isolated A548 object has 128 bytes of `.text` due to four padding bytes, but the actual `STT_FUNC` extent is 124 bytes. Preserving the original following function in the same source/linked layout yields the correct 124-byte ELF identity and exact 32 MiB ROM. Do not equate the padded section size with function length; never extend the function or add a synthetic symbol to hide padding.
- **Verified workaround:** keep precise multiline C statement boundaries and `i < end+1` source loop; pin authored C SHA-256 in the native reproducer. If adapting both to the same translation unit, public `void func_8000A5C4_B1C4(void*)` and typed local pointer avoids conflicting C prototype definitions without changing MIPS. Native codegen is not invariant to harmless C formatting changes. Any formatter must be followed by original native rerun.
- **Negative-control tests and commands:** `python3 tests/test_ido_source_lines.py --checkout PINNED --deps DEPS --runtime RUNTIME` PASS; flattening A548 C source lines alters 11 non-relocated MIPS words, joining A5C4's save/assignment alters two. GCC14.2 and Clang17 ASan/UBSan each PASS 4,096 actual-source tests per new function; three padding regression tests PASS. Six-source original-upstream verifier: `python3 verify_original_six.py --checkout PINNED --deps DEPS --runtime RUNTIME --out NEW_UNEXISTING --jobs 24` PASS.
- **Verification scope:** original SGI IDO/native instructions **204/204 new bytes**, plus four earlier research functions, combined **400/400 original code bytes**, full original pinned upstream USA **33,554,432/33,554,432 bytes exact**, **7,376/7,376 ELF FUNC identities** and **82,216/82,216 original-upstream relocations**. **Modern 1,965-accepted-USA canonical `decomp.verify`/82,103 semantic relocs, inventory and full local CI NOT RUN.** Status `RESEARCH_ONLY`. This observation is direct evidence for these two functions and source lines, not a universal IDO scheduling law.
