# Ebi Slide (Ebisu-pass): live Japanese reproduction and movement-state explanation

**2026-11-26 — RESEARCH_ONLY / LIVE_CLIP_OBSERVED.** The long-standing Ebi Slide glitch in Ganbare Goemon: Neo Momoyama Bakufu no Odori (Japan) has been reproduced by the user with ordinary scripted controller inputs in the native Mupen64Plus inspector. A successful trace (Q) and a 12.2435-second user screencast show a miniature-to-normal transformation with retained normal-size movement parameters, wall passage and subsequent out-of-bounds fall. This explains the movement-state mechanism that initiates the glitch; it does not yet establish the exact collision decision. Earlier grounded transformation movement was NOT the genuine slide. No claim of discovery of the input technique itself: the historical [2014 Japanese TAS submission, MATCH6974, Ebisu-pass](https://tasvideos.org/4375S) describes the landing-frame technique. The new contribution is the controlled live reproduction and correlation with original-ROM matching C and observed state.

## Why it happens: original code plus live observation

The already-promoted JP landing callback `func_801E46AC_5A067C` (USA `func_801DF3D8_59B2E8`) takes the nonneutral controller-magnitude branch: it writes the .7 constant to task+E8 and selects action 0D without replacing task+E4. This explains Q's retained normal-sized 2.8 on the first movement frame after landing. By contrast grounded miniature running action 0F selects the 1.12 speed profile. At frame 69, action returns to idle while E4/E8 are still 2.8/.7. Earlier dispatcher/eligibility analysis in #272 found that action 00 is eligible for C-Up deactivation while ordinary movement/stopping states are not. The neutral-frame path avoids parameter recalculation (the promoted JP `func_801E905C_5A502C` returns without writing E4/E8 on near-zero input; the promoted `func_801E8610_5A45E0` has a neutral path selecting idle). These functions are supporting static evidence, not proof of the exact instruction call path at every sample.

Scheduler research (#272) establishes pre/action/post callback order at task+8/+C/+10 (JP scheduler 800343A4, USA 80034734). The promoted JP post-update `func_801D1228_58D1F8` (USA `func_801CBAF8_587A08`) invokes `func_801D1BC0_58DB90(task, E4, E8)` when the system gate permits and then further update routines; it shifts the analogue history. Q establishes that the transformation action 8F retains both parameters over the entire 36-frame interval and permits movement. The most precise current explanation is an action-transition stale movement-profile bug: landing sets E8=.7 while leaving E4=2.8; one neutral frame returns to eligible idle with that profile intact; C-Up enters 8F before ordinary movement reinitializes it; the common post-update continues applying the stale normal-size limit while miniature. This explains the long-standing Ebi Slide's initiation, speed and the previously unexplained landing timing. We have reproduced clipping as a consequence of this sequence, but cannot yet say whether clipping is caused by size/collision shape, missed collision checks, coordinate correction, geometry/tunneling, or a combination. In particular do NOT equate E8 with instantaneous velocity, claim collision disabled, or treat the 4.059 displacement as a proven internal speed.
