## Verified source-structure discovery

The three **seven-command** texture sequences are generated exactly by genuine Nintendo/libultra header macros (as checked against original MIPS, not guessed opcode labels):

| Original mode | Macro | 32×32 texture | Tested Gfx result |
| --- | --- | --- | --- |
| 0 | `gDPLoadTextureBlock` | `G_IM_FMT_RGBA`, `G_IM_SIZ_16b` | Exact |
| 1 | `gDPLoadTextureBlock` | `G_IM_FMT_CI`, `G_IM_SIZ_8b` | Exact |
| 2 | **`gDPLoadTextureBlock_4b`** | `G_IM_FMT_CI`, dedicated four-bit macro | Exact |

The original macro arguments are 32×32, `G_TX_MIRROR` in S and T, mask 5, shift 0, and correct texture base/width handling.

**Negative control:** using generic `gDPLoadTextureBlock(...,G_IM_SIZ_4b,...)` instead of dedicated `gDPLoadTextureBlock_4b` produces a different DXT command: `F3000000 070FF800` instead of the original `F3000000 070FF400`. The wrong variant passes only **15/20** full rendering tests, with 48 mismatching command positions. Dedicated `_4b` passes **20/20**, zero mismatches. This is positive *and* negative evidence for the macro semantics, not proof that the original source literally invoked those macros.
