## Actual source experiment

For each of the **seven** IDO-generated MIPS variants, the full Gfx output agreed with the original across 20 scenarios (140/140 test runs; 37,128 / 37,128 Gfx commands, 0 mismatches). Every compiled candidate hit all four original-guard *conditions* (28/28 MIPS break events; exception instruction locations can differ).

The **unsigned 32-bit cache** is a plausible source type, not a proven original declaration. Compared with the signed diagnostic it creates eight newly identical **absolute-position** instruction words (mostly in the original div/page lookup range), loses three previously identical positions, and therefore improves **net +5 positions** without extending the first 13 consecutive identical instructions. The first mismatch remains ROM `0x69ED18`. New code is checked in as [`unsigned_tile_cache_DIAGNOSTIC.c`](unsigned_tile_cache_DIAGNOSTIC.c) and its [bounded evidence](evidence.json); **the source contains artificial stack-padding declarations**, which are not claimed to be the original Konami source.

**Negative compiler insight:** a genuine typed `struct { u32 w0, w1; } Gfx` with `Gfx* + 1`, instead of byte pointer +8, compiles to the same MIPS bytes and register assignments as the original research C. The register mismatch is not caused simply by the display-list pointer type or by signed vs unsigned stored Gfx words. All seven `-O2` variants still hoist `F300` and `E700` into **one** LUI apiece and allocate long-lived constants unlike original, which loads each constant **three** times within format branches. The original allocates `0x07054150` to `$fp`, `0xE6000000` to `$ra`; these relationships remain unresolved.
